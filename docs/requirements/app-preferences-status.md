# App 偏好与服务状态

> 状态：基础状态页与本地选择控制已合并；Android 本地每日提醒位于 `agent/local-learning-reminders`，自动门禁、模拟器 schedule/cancel、重启恢复、跨时区当地时间保持、Sony 通知展示、后台限制检测和解除限制后的后台熄屏真实到点均通过；尚未提交、推送或运行远端 CI
> 日期：2026-07-27

## 用户问题与目标

当前 Settings 已能查看帮助、隐私、条款、本地数据和版本，但用户无法在一个明确入口确认界面语言、课程语言、音频/麦克风边界，以及通知、诊断、账号和同步是否真的启用。

“App preferences”先以离线只读状态页交付，随后加入通知与可选诊断的本地选择。当前切片把通知选择升级为 Android 本地每日学习提醒；诊断仍只是未来服务选择，不能被表述为已经发送数据。

## 主路径与状态

1. 用户从 Settings 打开 App preferences。
2. 页面展示：
   - 界面语言为 English，当前不能切换；
   - 学习内容为 Simplified Chinese，并提供拼音和英文引导；
   - 已下载课程音频可离线播放；
   - 麦克风仅在用户开始口语录音时请求，拒绝后仍可自评继续；
   - Android 可在本机安排每日学习提醒；远端推送、分析/崩溃服务、账号与同步尚未接入；
   - 提醒与分析/崩溃选择默认关闭，可独立开启或撤回。
3. 用户打开提醒时先选择本地时间；取消选择不请求权限、不改变状态。确认后先检查 Android 是否明确限制该 App 的后台工作；受限时保持 Off 并提供系统设置入口，不继续请求权限或调度。
4. 后台工作可用时才读取或请求 Android 通知权限；权限允许后，用稳定通知 ID 安排不精确的本地每日提醒。系统拒绝、永久拒绝、平台不可用和调度失败分别反馈，开关保持关闭。
5. 调度和偏好写入都成功后页面才显示 On；关闭时先取消已安排提醒，再写回 Off。失败时尽量恢复之前的有效状态。
6. 重新打开 App 后选择和提醒时间仍然存在；用户可返回 Settings，页面不依赖网络、账号或外部配置。

本机偏好读取期间显示加载状态；读取失败时不猜测当前值，提供重试。账号与同步继续显示不可用状态。

## 数据与隐私边界

- 提醒状态、每日分钟数和诊断选择分别保存在 `preferences.notifications.enabled.v1`、`preferences.notifications.reminder_minutes.v1` 与 `preferences.diagnostics.enabled.v1`；默认均不启用，不修改 Drift Schema。
- Android 只接本地通知调度，不新增远端 API、推送 Token、分析/崩溃 SDK 或待发送队列；使用 `inexactAllowWhileIdle`，不申请精确闹钟权限。
- Manifest 声明重启后恢复本地提醒所需的 `RECEIVE_BOOT_COMPLETED`，并由专用接收器在 `TIMEZONE_CHANGED` 后把稳定提醒重排到新时区的下一次当地时间；通知运行时权限只在用户确认时间后请求。打开页面本身不会请求麦克风、通知或跟踪权限。
- 不上传学习数据、录音、诊断信息或设备标识。

## 验收标准

- Settings 中存在可发现的 App preferences 入口。
- 页面逐项显示语言、学习内容、音频、麦克风、通知、分析/崩溃和账号/同步状态。
- 提醒与分析/崩溃选择默认关闭；提醒可选择时间、跨 App 进程恢复并再次关闭，关闭会取消稳定 ID 对应的本地调度。
- 页面明确区分本地提醒、远端推送与诊断服务；开关打开不能被表述成已发送数据或已验证到点投递。
- 普通拒绝、永久拒绝、平台不可用与调度/存储失败都不虚报开启；永久拒绝提供系统设置入口。
- 读取失败提供重试；写入失败保留之前的选择并显示明确错误。
- 返回关系正确；在 360×800、200% 文字缩放下可滚动且无溢出。
- 两个开关具有开/关语义与至少 44×44dp 可点击区域。
- 现有 Settings、课程和主导航测试继续通过。

## 当前验证

- Flutter format 90 files / 0 changed、analyze 0 issues、全量 104 tests 与 Debug APK 通过；Android 集成测试在 `emulator-5554` 真实调用通知插件完成 schedule/cancel。
- 模拟器 UI 已覆盖时间选择、系统权限弹窗、On/Off 反馈；插件缓存确认稳定 ID `41001`、本地时区、`inexactAllowWhileIdle` 和关闭后的空调度列表。
- Sony `XQ-DQ72`（Android 15）已覆盖时间选择、系统通知权限、On 状态、`Asia/Hong_Kong` 调度缓存与真实通知栏展示。18:50 Alarm 在 App 后台时超过 inexact 最晚窗口约 7 分钟仍未派发，解锁也未补发；19:00 把 App 切到前台后通知立即出现并续排次日。设备当时的 `RUN_ANY_IN_BACKGROUND` AppOp 为 `ignore`，因此当前真机结论是“通知接收/展示/续排可用，但后台真实到点投递失败”，不是完整通过。
- 随后的修复通过 `ActivityManager.isBackgroundRestricted()` 识别这一状态。Sony 再测时开关保持 Off，显示后台限制原因和系统设置入口，不新增通知权限请求、缓存或 Alarm；按钮准确打开本 App 的应用信息页。验收后插件缓存仍为 `[]`，无活动通知或次日 Alarm。
- 用户解除 Sony 后台限制后，19:30 Alarm 在 App 退到桌面、手机熄屏且保持 Dozing 时于约 19:33:43 实际投递，并自动续排次日 19:30；后台真实到点通过。模拟器在 App 未启动时重启后由 BootReceiver 重建同一 12:30 Alarm；GMT → 香港的首次黑盒测试先发现旧 Alarm 锚定 UTC，新增时区接收器后 HKT → GMT 与 GMT → HKT 都保持当地 12:30，若当天已过则排到次日。模拟器最终恢复 GMT、提醒 Off、缓存与 Alarm 清空。
