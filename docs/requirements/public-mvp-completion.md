# 公开 MVP App 完成门禁

> 状态：执行中
> 最近核对：2026-07-27
> 本文是“App 做到什么程度才能开始上架”的单一权威清单。`README.md` 和 `docs/开发方案.md` 只保存摘要并链接到这里。

## 1. 产品决定

- 上架是最后一个阶段，不是 M1、M2 或 GitHub Pre-release 完成后的自然下一步。
- 当前 `0.2.0+3` 证明 3 个地点、12 节课和 3 个地点终局的本地学习原型可安装、可运行；它不是公开 MVP，也不是商店候选版本。
- “App 完成”以仓库已经定义的公开 MVP 为边界：6 个地点、约 30 节课，以及设置与客服、隐私与数据控制、账号与同步、订阅、基础语音、分析与崩溃监控、每日任务、连胜和印章册。
- Android 可以先发布、iOS 后发布，但每个平台提交前都必须完整通过本文件的 App 内门禁；不能用“另一平台以后再补”掩盖当前提交平台的缺失功能。
- 为实现登录、订阅或恢复购买而进行 Apple/Google 沙箱配置属于功能开发依赖，不等于开始商店发布。正式签名、商店素材和审核提交仍放在最后。

## 3. App 内必须完成的能力

### G1：完整产品外壳与设置

- 首次使用引导：说明产品价值、学习目标、可离线能力；不强迫登录才能体验本地核心课程。
- 稳定主导航：Journey、复习/练习、个人或进度、设置等主要入口可发现且返回关系一致。
- 设置中心至少包含：界面/内容语言、音频与麦克风说明、通知开关、分析与崩溃收集选择、账号与同步、数据管理、帮助与客服、隐私政策、服务条款、版本号与构建号。
- 所有主要页面覆盖加载、空数据、失败、重试、离线、会话过期、无权限和服务维护状态，不能留占位文案、死链接或空页面。
- 本地学习者可以清除本机学习数据；危险操作必须说明影响、二次确认并提供可验证结果。

### G2：客服、隐私和数据控制

- App 内提供“帮助与客服”：常见问题、联系支持、报告问题、购买/退款帮助和回复预期。
- 使用真实可收件的支持邮箱或工单地址及真实支持网页；App、Google Play 和 App Store 的联系方式保持一致并持续可用。
- 报告问题只附必要诊断信息，如 App 版本、系统版本和匿名错误编号；不得附 Token、邮箱、原始录音、完整转写或购买票据。
- App 内以易发现入口展示真实、公开可访问的隐私政策和服务条款，不使用空白页或临时 URL。
- 隐私政策逐项说明：账号信息、学习记录、麦克风与临时录音、同步、分析、崩溃、购买记录、第三方 SDK、处理目的、保存期限、共享对象、安全措施、用户选择和联系渠道。
- 非必要分析、崩溃和营销通知在收集前给出清晰选择；麦克风继续按实际使用时机说明用途并请求系统权限，拒绝后保留可完成的降级路径。
- 建立逐版本数据清单，核对代码、SDK、权限、隐私政策、Google Data safety 和 Apple App Privacy 的说法一致。
- 提供清除本地数据、撤回可选收集、查看隐私选择和请求删除的入口；删除结果和依法保留的例外必须说明。

### G3：账号生命周期与跨设备同步

- 保持本地优先：不登录也能完成核心课程；需要跨设备同步或恢复购买时再引导创建账号。
- Android 接入 Google 身份，iOS 接入 Apple 身份；若 iOS 使用第三方社交登录，登录选项必须满足 Apple 对等登录要求。
- 服务端实现身份令牌交换、短时访问令牌、刷新令牌轮换与哈希存储、会话失效、退出当前设备和必要的全部设备退出。
- 支持匿名本地数据合并到账户，重复执行不产生重复进度；失败时保留本地数据并可重试。
- 实现 Outbox 批量上传、幂等去重、游标、重试、弱网恢复、内容版本兼容和多设备冲突规则；跨设备不得覆盖已完成课程或错误相加连胜。
- API、数据库迁移和 Repository 对所有用户数据执行明确的 `user_id` 边界，并测试未登录、过期 Token、伪造 Token 和跨用户读写均被拒绝。
- 账号设置内提供完整账号删除，不用“停用账号”代替删除；删除覆盖会话、账号、学习数据、对象存储和第三方身份映射。
- Google Play 还要求提供可公开访问的网页删除申请入口；Apple 要求能从 App 内发起删除。删除需要时间时显示预计时限并在完成后通知。
- 删除前说明仍在续费的商店订阅如何取消；账号删除本身不能被联系客服、发邮件或不必要步骤阻断。

### G4：公开 MVP 学习、激励与付费闭环

- 扩展到 6 个地点、约 30 节课；每个发布单元通过内容校验、中文教学审核、英文自然度审核、音频听感、资产许可和真实设备逐页验收。
- 三星、每日三任务、连胜、休息券、地点印章和终局挑战全部由真实学习事件驱动，升级、重启、跨时区和跨设备后保持一致。
- 基础语音能力按既定分层实现，失败或低置信度不判整课失败；默认不上传或长期保存原始录音，任何变化都重新进入隐私评审。
- 接入 Apple/Google 平台购买能力、商品展示、购买、待处理、取消、退款、过期、恢复购买、权益缓存和服务端通知；数字课程/订阅遵守目标商店的支付规则。
- 付费墙清楚说明价格、周期、自动续费、获得内容和管理/取消方式；登录、权益和账号删除对订阅状态的影响可解释。
- 接入最小分析、崩溃监控和 Feature Flag；事件只含必要字段并去标识化，不上传录音、自由文本或凭据。

### G5：质量、安全与可运营性

- 自动测试覆盖首次启动、课程、复习、账号、匿名转登录、同步冲突、删除账号、购买/恢复、订阅变化和升级迁移。
- 手工矩阵覆盖 Android 低端/主流设备、目标 iPhone、无网/弱网/网络切换、麦克风拒绝与中断、时区变化、大字体和屏幕阅读器。
- 主要页面通过 200% 字体、触控目标、对比度、语义标签、减少动态效果和键盘/读屏顺序检查。
- 验证启动时间、课程滚动/音频性能、内存、耗电、缓存上限、数据库迁移、旧版本升级和回滚；阈值在进入封闭测试前写入可重复的发布门禁。
- API 具备限流、输入验证、超时、结构化错误、密钥轮换、审计日志、备份/恢复和依赖故障降级；日志不含敏感数据。
- 客服流程真实跑通：测试者能提交问题，维护者能用匿名错误编号定位版本和失败环节，并能发布已知问题与恢复说明。

### G6：封闭测试与产品验收

- 真实目标用户在无口头指导下完成首次使用、第一课、复习、账号同步、购买恢复和联系客服。
- 高优先级崩溃、数据丢失、购买错误、账号删除错误、死链接和阻断流程全部清零。
- 激活、D1/D7、7 日回忆率、语音失败、崩溃和退款数据可计算；是否继续发布有明确结论。
- 产品负责人对目标平台的完整 App 做最终验收，不用单个里程碑、绿 CI、模拟器或 GitHub Pre-release 代替。

## 4. 放行规则

只有以下项目全部勾选，才能把版本称为“商店候选”：

- [ ] G1 完整产品外壳与设置通过；
- [ ] G2 客服、隐私和数据控制通过；
- [ ] G3 账号生命周期与跨设备同步通过；
- [ ] G4 公开 MVP 学习、激励与付费闭环通过；
- [ ] G5 质量、安全与可运营性通过；
- [ ] G6 封闭测试与产品验收通过；
- [ ] 隐私政策、服务条款、支持页面和删除申请页面均为真实生产 URL；
- [ ] 代码/SDK/权限/数据清单与商店披露已完成逐项核对。

任一项未完成，下一步仍是 App 产品开发或质量修复，不是商店签名、截图或提交审核。

## 5. 当前实施顺序

1. **继续完成信任外壳**：主导航、设置、帮助/隐私/条款状态页、本地数据清理和版本信息首切片已经落地；继续补首次使用引导、其余设置项、真实支持渠道、正式政策/条款和真机验收。
2. **再做账号与同步**：先写数据和会话契约，再实现 API/DB、客户端登录、匿名迁移、跨设备同步和完整删除。
3. **补齐公开 MVP 功能**：6 个地点/约 30 节课、真实每日任务/连胜/印章、订阅权益、基础语音、分析与崩溃监控。
4. **做系统级验收**：弱网、升级、无障碍、安全、性能、购买、账号删除、客服和封闭测试。
5. **最后才做上架**：正式签名、商店资料、审核账号、分阶段发布与回滚。

第一个开发切片定义为“App 设置与信任中心”：生产路由和页面骨架、帮助/联系客服、隐私与条款入口、数据管理入口、App 版本信息，以及对应加载/失败/离线和无障碍测试。未取得真实邮箱、URL 和法律主体前，可以完成结构和测试，但不得把占位值标为完成。

## 6. 上架阶段仍需完成的事项

这些事项是最终阶段，不是当前优先级：

- 开发者账号和法律身份核验、包名/Bundle ID、正式签名密钥和安全托管；
- Android AAB、iOS Archive、版本号、目标 API/SDK、隐私清单和平台兼容要求；
- 商店名称、说明、关键词、截图、图标、分类、年龄/内容分级、目标受众和地区；
- Google Data safety、Apple App Privacy、隐私政策 URL、支持 URL、账号删除网页和付款声明；
- 审核说明、可用的审核账号或完整 demo 模式、后端生产环境和购买商品；
- Google 测试轨道要求（若开发者账号适用）、TestFlight/封闭测试、分阶段发布、监控和回滚。

目标 API、SDK、测试轨道和支付政策会变化，必须在真正提交前重新核对官方最新要求，不能把本文件的 2026-07-27 快照当作永久规则。

## 7. 必须由产品负责人提供的生产信息

- 运营/法律主体名称、注册地区和隐私联系身份；
- 可公开且有人处理的支持邮箱、支持网页和域名；
- 首发国家/地区、目标年龄以及是否明确排除儿童受众；
- 最终登录方式和账号恢复方式；
- 订阅商品、价格、试用、地区、权益和退款支持口径。

这些信息不阻塞页面结构与后端契约开发，但在 G2、G3、G4 关闭前必须使用真实值完成验证。

## 8. 官方要求依据

- [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)：提交应为完整版本；App 和 Support URL 必须提供可用联系方式；隐私政策需在 App 内易于访问；创建账号后必须支持 App 内删除。
- [Apple：Offering account deletion in your app](https://developer.apple.com/support/offering-account-deletion-in-your-app/)：账号删除应易找、删除整个账号及相关数据，并说明订阅影响。
- [Apple App Privacy](https://developer.apple.com/help/app-store-connect/reference/app-information/app-privacy/)：所有 App 都需要 Privacy Policy URL，披露还要覆盖第三方代码的数据处理。
- [Google Play User Data / Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)：所有发布 App 都要准确声明自身及第三方 SDK 的数据收集/共享，并提供隐私政策。
- [Google Play account deletion](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)：App 内创建账号时，需要 App 内删除路径和公开网页删除申请入口。
- [Google Play Payments](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)：通过 Play 分发的数字功能和订阅默认使用 Google Play Billing，适用例外需按地区和政策判断。
- [Google Play testing for new personal accounts](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)：2023-11-13 后创建的适用个人账号，在申请正式发布前需满足封闭测试人数和连续时长要求。
- [Google Play target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-GB_ALL)：目标 API 要求按年度变化，提交前必须重新核对。
