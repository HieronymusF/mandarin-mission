# Mandarin Mission 功能开发流程

本流程面向一人开发和 AI 协作。默认采用“需求清楚后直接组合 UI 组件并做垂直切片”，不再要求先画 Figma 原型。Claude Code 在 2026-07-17 提交的阶段产物、门槛、接口先行和测试规则继续保留；强制 Figma、节点链接审批和所有任务同等重量的流程已移除。

## 0. 先判断任务等级

| 等级 | 典型任务 | 必需文档 |
|---|---|---|
| S | 文案、现有组件内的小改动、无 UI 规则修复 | Issue/任务描述即可 |
| M | 新页面、新状态流、跨 ViewModel/Repository 的功能 | `docs/requirements/<feature>.md` |
| L | 新导航域、付费/账号/同步、不可逆架构或全新交互模型 | 需求文档 + ADR；必要时补视觉探索 |

任务等级只决定过程重量，不降低测试和安全要求。发现风险扩大时升级等级，不把原任务静默扩成大重构。

## 阶段 1：定义可交付切片

**目标**：把“要做什么”压缩成一次可验证的用户结果。

M/L 需求文档至少包含：

- 用户问题与目标；
- 主路径和必须覆盖的加载、空、错误、不可用状态；
- 数据来源与本地/远端边界；
- 接口或 Repository 契约；
- 验收标准；
- 明确不做的范围；
- 受影响的指标、Schema、迁移和隐私项。

**门槛**：

- 用户结果可以通过测试或重复手工步骤判断；
- 接口契约足以让数据层与 UI 独立推进；
- 没有把计划写成已实现事实。

## 阶段 2：从 UI 素材库选组件

UI 任务按 `docs/design-system.md` 执行：

1. 从 shadcn 官方目录确定语义组件；
2. 官方目录不足时，从 `awesome-shadcn-ui` 发现候选组合、主题或交互模式，并返回候选的原始来源；
3. 核验原始来源的许可证、维护状态、移动端适用性和无障碍风险；
4. 使用 Flutter `shadcn_ui`、Lucide、项目令牌和共享组件完成对应实现，不复制 React/Tailwind 代码；
5. 列出页面需要的原语、项目级组合组件和全部状态；
6. 只补当前切片缺失的令牌或组件。

标准按钮、卡片、徽章、进度、表单和反馈不画原型，直接进入代码。只有以下情况才增加视觉探索：

- 品牌首屏、地图、插画或商店素材；
- 组件库没有对应模式的复杂手势或导航；
- 两种方案会显著改变产品路径，且代码试错成本高；
- 用户明确要求 Figma、视觉稿或多个方向。

视觉探索可以是 Figma、静态图或小型代码实验；它是风险控制工具，不是所有 UI 的门票。

**门槛**：

- 使用现有语义令牌和组件白名单；
- 不引入第二套 UI 库；
- 外部候选已记录原始来源和许可证；目录型聚合仓库的许可证不被当作外链项目授权；
- 正常、加载、空、错误、不可用和提交中状态已有处理方案；
- 正式可见资产有来源与授权。

## 阶段 3：建立状态和契约

**前端**：

- View 只渲染状态并转发用户意图；
- ViewModel/Controller 处理提交、判分、导航前置条件和错误；
- Repository 负责本地/远端数据访问；
- 纯规则进入 `learning_core` 或纯 Dart domain，并先写单元测试。

**后端/数据层**：

- 有远端需求时按阶段 1 契约并行实现 Go API、迁移和 Provider；
- 后端未就绪时只在 ViewModel/Repository 边界使用确定性 fake，不把 mock 散在 Widget；
- 本地功能直接使用 Drift/Repository，不为“未来云同步”预建空接口。

**门槛**：

- 异步操作有提交中、失败与重试；
- 用户操作先落本地事务并写 Outbox，UI 不等待云端成功；
- 数据迁移、隐私和回滚影响已说明。

## 阶段 4：实现一个端到端切片

推荐顺序：

1. 最小失败测试或状态测试；
2. domain/Repository；
3. Controller/ViewModel；
4. 使用 shadcn 原语完成 View；
5. 路由与真实数据接线；
6. 同步文档和生成文件。

实现规则：

- 一个文件只承担清晰职责；页面按独立步骤或稳定组件拆分；
- 不在按钮回调里直接计算业务结果或调用 Repository；
- 不复制 shadcn 原语做近似组件；
- 第二次出现相同组合后再提炼到 `lib/shared`；
- 不因重构顺手增加产品范围。

**门槛**：

- 主路径可从入口走到结果；
- 断网或外部服务失败不阻断已下载课程和复习；
- 没有吞掉的 Future 或可重复提交；
- 关键文案来自内容数据或未来可本地化的集中入口。

## 阶段 5：分层验证

按风险由近到远执行：

1. format、静态分析；
2. domain 单元测试；
3. Repository/迁移测试；
4. Widget 测试；
5. 端到端集成测试；
6. 内容 Schema/资产校验；
7. 常见 Android 尺寸、小屏、200% 字体和无障碍检查；
8. UI 任务保存关键状态截图；发布前在真实设备验证；
9. API 变更运行 Go vet/test 和 Docker build。

Golden 测试用于稳定的关键页面，不为频繁变化的探索页面制造高维护快照。

**门槛**：

- CI 全绿；
- 新增失败路径有测试或可重复手工记录；
- UI 无溢出、遮挡、错误层级、随机颜色/圆角；
- `AGENTS.md` 的完成标准全部满足。

## 阶段 6：交付与里程碑更新

草稿 PR 包含：

- 用户结果与范围；
- 关键实现决策；
- UI 前后或关键状态截图（有 UI 时）；
- 自动与手工验证；
- Schema/迁移/隐私影响；
- 已知限制和回滚方式。

Figma 链接只在本任务实际使用 Figma 时提供，不再是通用门槛。完成后同步 `README.md`、`AGENTS.md`、项目状态和里程碑；不要保留会误导下一个代理的旧交接指令。

## 产品里程碑

| 里程碑 | 当前范围 | 放行条件 |
|---|---|---|
| M0 工程基线 | Flutter、Dart 核心、内容 Schema、Drift、Go 容器、CI | 新电脑可构建和测试 |
| M0.5 代码优先 UI 基线 | shadcn 主题、Journey、课程播放器、组件/流程文档 | 现有 UI 迁移完成，测试与 APK 构建通过 |
| M1 点咖啡垂直切片 | 1 地点、1 完整课、音频/录音、到期复习 | 真机完成课程，重启保留进度，正确时间出现复习；飞行模式可用 |
| M2 可玩循环 | 3 地点、12 课、三星、每日任务、连胜、印章、终局挑战 | 10—15 名体验者无需解释完成首日；内容可不改客户端扩展 |
| M3 封闭测试 | 30—50 名英语使用者 | 可计算激活、D1/D7、7 日回忆、语音误判；有 Go/Adjust/Stop 结论 |
| M4 公开 MVP | 6 地点、约 30 课、同步、订阅、基础语音、分析 | 跨设备、购买恢复、删除账号、无障碍和商店材料通过 |
| M5 发布观察 | Android 分阶段发布，稳定后 iOS | 崩溃、漏斗、语音、订阅和内容错误可观测，指标决定是否扩展 |

里程碑只按可验证结果放行，不按代码量、页面数量或文档完成度判断。
