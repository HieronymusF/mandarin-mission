# Mandarin Mission 功能开发流程

每个功能（feature）从立项到交付，按以下阶段推进。每个阶段有明确的**产物**和**进入下一阶段的门槛**；未达标不得进入下一步。

纯本地、无 UI 的特性（如算法、数据层、CI 改动）可跳过设计相关阶段（阶段 2、3a、4 的视觉部分），按 `AGENTS.md` 的信息优先级判断，但需求文档和测试两段仍然适用。

分工前提（见 `AGENTS.md` 第 1 节）：
- Figma 上设计、画原型由具备 Figma 插件能力的 AI 代理（如 codex、Claude）主导，人类辅助改动。
- 当前接入的代理（ZCode/GLM）没有 Figma 画图能力，只读取已确认的 Figma 设计稿并实现为代码。
- 所有 AI 代理都可参与其余代码实现（Flutter、Go、Dart 核心、Drift、CI、内容校验、测试等）。

---

## 阶段 1 · 需求文档（Markdown）

**谁做**：AI 代理起草 → 人类审核。

**产物**：`docs/requirements/<feature>.md`，包含：
- 功能目标
- 用户故事
- 涉及的页面与交互
- 接口契约（前端需要后端提供什么：路径、入参、返回、错误码）
- 验收标准
- 本期范围边界（明确不做什么）

**进入下一阶段的门槛**：
- [ ] 人类审核通过（在文档里留审核痕迹或签字行）
- [ ] 接口契约已定义（供阶段 3b 后端并行启动）
- [ ] 范围边界写明，防止顺手扩大

> 接口契约提前定义，是让阶段 3 后端能和设计并行的前提。

---

## 阶段 2 · Figma 设计规范（搭框架）

**谁做**：有 Figma 插件能力的 AI 代理主导，人类辅助。

**产物**：
- 仓库内 `docs/design-system.md`：色板、字号阶梯、间距 token、圆角、组件清单（按钮、卡片、输入、反馈条等）、状态定义（正常、加载、空、错误、不可用）。
- Figma 文件内对应的 Variables / Styles / Components，与文档双向对齐。

**进入下一阶段的门槛**：
- [ ] 设计规范已通过人类审核
- [ ] 仓库文档与 Figma 一致（改一处必须同步另一处）

> 设计规范一旦确认，后续所有页面与组件必须严格遵守，不得各页面自行其是。

---

## 阶段 3 · Figma 画原型 + 后端配置（并行）

两条线**同时**进行，因为阶段 1 已经定义了接口契约。

### 3a · Figma 原型

**谁做**：有 Figma 画图能力的 AI 代理主导，人类辅助改动。

**产物**：在统一设计文件 `Learn Chinese` 的 `Page 1` 画出本功能的全部页面、关键交互，以及正常、加载、空、错误、不可用状态。严格遵守阶段 2 的设计规范。

**门槛**：
- [ ] 人类确认节点级 Figma 链接（参考 `AGENTS.md` 前端任务的 Figma 前置流程）

### 3b · 后端配置

**谁做**：AI 代理。

**产物**：Go API 端点、数据库迁移、Provider 适配器；按 `docs/开发方案.md` 的云端表与同步规则；配套单元测试。

**门槛**：
- [ ] 接口符合阶段 1 契约
- [ ] CI 通过

---

## 阶段 4 · 前端严格还原 UI

**谁做**：AI 代理（含无 Figma 画图能力的代理，如 ZCode）。

**输入**：阶段 3a 确认的 Figma 节点链接 + 阶段 2 的设计规范。

**产物**：Flutter 代码，**1:1 还原 Figma**，复用设计系统的 token 和组件，不自造视觉。后端未就绪时使用本地 mock 数据先行，不必卡在后端上。

**门槛**：
- [ ] 实现与 Figma 截图比对一致；任何差异必须在 PR 里说明
- [ ] Widget 测试通过

---

## 阶段 5 · 前后端联调

**产物**：前端切到真实后端，跑通端到端路径；处理断网、超时、服务失败的降级。

**门槛**：
- [ ] 核心路径在真实设备上跑通
- [ ] 本地优先不变量成立（见 `AGENTS.md` 第 6 节：断网时课程、进度、到期复习仍可用）

---

## 阶段 6 · 测试

**产物**：按 `docs/开发方案.md` 第 17 章执行——单元、Repository、Widget、Golden、集成、内容测试，以及手工测试矩阵。

**门槛**：
- [ ] CI 全绿
- [ ] 完成 `AGENTS.md` 第 13 节的完成标准

---

## 阶段 7 · 交付

草稿 PR 必须包含：
- 已确认的 Figma 节点链接
- 实现与原型的差异说明（无差异也需明确写明）
- 验证结果（测试与手工验证）
- 已知限制

满足 `AGENTS.md` 的 Git 工作规则后合并到 `main`。
